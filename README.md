# 中国艺术史知识库

先秦至当代 **121 家**艺术家的全维度档案，单文件 HTML，离线可用。

双击 index.html 即可

## 体例

三类实体，各有固定结构。**新增条目必须照此，否则 `validate.py` 报错。**

### 画家（`t-artist`）十二维

`概览 / 基础档案 / 人生轨迹 / 人物关系 / 创作体系 / 历史坐标 / 世俗生活 / 八卦与传奇 / 语录库 / ★代表作·独立条目 / 代表作总表 / 争议字段`

- 各家可另加独有维度（如傅山的"医学与金石"），但上列不可缺
- `★` 区块为索引卡片区，收录该家的作品与事件条目

### 作品（`t-work`）八节

`基础信息 / 创作背景 / 画面分析 / 技法与创新 / 来源与流转 / 评价与影响 / 观看指南 / 争议字段`

必须有 `.backlink` 返回作者、`<footer>` 注明来源。

### 事件（`t-event`）三节

`事件经过 / 字段 / 争议字段`

必须有 `.backlink`、`<footer>`，且必须被某位画家的"关键事件索引"收录。

## 编纂方针

这几条是内容判断的准绳，不是文风偏好。

**1. 史料稀疏处如实标注，不妄补。**
用 `<span class="gap">· 暂无可靠资料</span>` 标出空缺，而不是填入合理推测。古人条目里大量出现是正常的。

**2. 无款作品一律标"传"。**
并在争议字段写明方法论风险。例如：范宽可确证者仅《溪山行旅图》一件，以单一基准件判定其余作品样本过窄；巨然、周昉名下无一件有款作品，所谓"某某风格"是由若干无款传世品互相定义出来的，存在循环论证。

**3. 争议并陈，不替读者裁断。**
`stmt` 四态标明每条陈述的地位：

| 类 | 含义 | 视觉 |
|----|------|------|
| `adopt` | 本库采纳 | 绿色左边框 |
| `pend` | 待校验 / 材料不足 | 灰色左边框 |
| `disp` | 有争议、存异议 | 橙色左边框 |
| `dep` | 旧说，已被质疑或推翻 | 红色左边框 + 降透明度 |

**4. 事件维度按史料择要，非每家皆有。**
生平只有一两句记载的画家不强立事件条目——这是完成，不是遗漏。首页已写明此方针。

**5. 不作回溯性诊断、不作单因归结。**
不给古人安现代精神病名（徐渭、八大山人、石鲁条目均明示此点）；不把风格突破简单归因于苦难或伤病（黄庭坚、陆俨少、林散之条目均明示此点）。

**6. 徽章语义**

| 类 | 用于 |
|----|------|
| `b-ok` | 已验证 / 有款可考 / 文献明载 |
| `b-neu` | 待校 / 口径不一 / 无资料 |
| `b-warn` | 有争议 / 存疑 / 需审慎 |
| `b-dep` | 已佚 / 旧说已被推翻 |

## 改动方式

> **不要手改 index.html 里的任何计数。** 计数由脚本从实际卡片推导回写，手改必然漏。

### 加条目

```bash
# 加画家（同时处理 view、首页卡片、侧栏索引、labels 映射、全部计数）
python tools/entry.py artist --id liusongnian --name 刘松年 --pinyin "Liú Sōngnián" \
    --cat 绘画 --small 绘 --sub "南宋" --one-line "南宋四家,暗门刘" \
    --after artist-litang --fragment frag.html

# 加作品（自动挂到作者的 ★ 索引区）
python tools/entry.py work --id liusongnian-01 --title 四景山水图 --artist liusongnian \
    --tag "画作 南宋" --meta "绢本设色·故宫博物院" --desc "宋代四季组画的典范" \
    --fragment frag.html

# 加事件（索引区不存在则按房规新建）
python tools/entry.py event --id fushan-hongru --title 拒博学鸿儒科 --artist fushan \
    --tag "事件 1678" --meta "康熙十七年" --desc "清初士人最著名的一次沉默对抗" \
    --fragment frag.html

# 只重算计数
python tools/entry.py resync
```

`--fragment` 指向一个只含该条目 HTML 的片段文件。写片段时**照抄一个同类现有条目的结构**最省事。

一件作品/事件若由多人共有（如《江山如此多娇》、人民英雄纪念碑浮雕），条目挂一处，索引卡可用 `entry._append_ixcard()` 补挂到其他人名下。

### 校验

```bash
python tools/validate.py          # ERROR 必须为 0，否则退出码 1
```

查这些：

- 死链与孤儿条目
- 五处计数一致性（图录 / 筛选器 / 朝代 / 卡片 / 侧栏）
- 面包屑身份与卡片类别是否相符
- **外文同形字**——曾在实体 ID 里查出西里尔 `а/н/о` 冒充拉丁 `a/n/o`，肉眼不可辨却使该 ID 无法检索
- 画家十二维齐全、作品回链作者、事件三节齐全且被索引收录

`entry.py` 每次写入后会自动跑一遍。

### 为什么没有构建脚本

原有的 `build_site_120.py` 等生成脚本已丢失，且内容早已在单文件里手工演进多轮。把 8 MB 手写文稿反向抽成数据是**有损的**，不值得。因此不重建整站生成器，只提供"安全地往里加一条"的能力。

`entry.py` 的写入为**原子替换**（临时文件 + `os.replace` + 重试）：直接 `open(...,'w')` 会立即截断原文，写到一半失败就只剩 git 能救；且本地起预览服务器时 Windows 会锁住文件，直接写会失败。

### 本地预览

```bash
python -m http.server 8731        # 然后开 http://127.0.0.1:8731/index.html
```

注意：**服务器运行时会锁住 index.html**，此时跑 `entry.py` 可能写入失败（会重试并明确报错，原文件不动）。改动前先停掉。
