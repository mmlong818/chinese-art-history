# 缺口填充 · 作业须知

`plan/gaps/{artist,work,site,class,treatise,event}.json` 是工单，
每项带 `name`（提纲点的名字）、`hits`（被几个提纲单元点到）、`cells`（落在哪些期×门类）。

**你会被分配一个切片（文件名 + 起止序号）。只做你那一段。**

## 零、范围硬约束（2026-08-06 起，优先于本文其余各节）

**不要再引入任何海外博物馆的藏品。新建与扩充一律以中国境内书画为核心。**

- **境内**包括北京故宫、台北故宫、辽宁省博物馆、上海博物馆、南京博物院、
  各省市博物馆、考古所、寺观与原址等。台北故宫属境内，不在此限。
- **已建的海外藏品条目保留不动**——本约束是「不要再引入」，不是清退。
- **若某件一等中国书画只存于海外**（女史箴图、照夜白图、溪岸图一类），
  **不要擅自新建，先在报告里提请协调方判断。**
- 海外馆方数据仍可作为**佐证**引用（如某境内藏品的著录、比较件），
  但不得据以新建海外藏品的条目。

**这条约束的由来，是一次真实的资源错配**：本库书画按藏地统计，
克利夫兰美术馆 543 条、北京故宫 123 条、辽宁省博物馆 18 条、沈阳故宫 0 条——
**一直在给收藏最弱的一家补数据。**已据此撤销 17 份克利夫兰升级工单（219 条），
见 `plan/gaps/upgrade/_CANCELLED-cma.md`。

## 一、必读

1. **`schema.py`** —— 契约。按你的实体类看对应的 `*_SECTIONS`、`DISPUTES`、
   `STMT_STATES` 四态、`VERIFICATION` 三档、`BLOCKS`、`IMAGE_STATUS`、
   `CLASS_FACETS`（**十一档**）、`HOLDER_ALIAS`、`ARTIST_CAT`、`WORK_KIND_GROUP`。
2. **同类的三条现成条目**当范本。`ls data/<sub>/` 后挑三条读完。
3. **`data/outline.json`** —— 找到点了你这些名字的单元，看它期望这条承担什么。
4. **`data/canon.json`** 相关各期。
5. **`data/sources.json`** —— 175 条，**只能引已登记的 id**。

## 二、十条硬约束

一、**`name`／`title` 与工单里的 `name` 字字相同。**对账按名比对。
   写错一字，这一条就仍算缺口，你的活白做。

二、**只写完整级（不设 `depth`，或写 `depth: "full"`）。**
   著录级是照录，本库已有 3,400 条照录；**用户明确要的是完整级。**

三、**`verification` 一律 `memory`**，除非你真核过馆藏页或考古报告。
   其含义是「未经外部核对——所有具体数字、年代、尺寸应视为待校验」。
   **谎报核实级别比缺内容严重得多。**尺寸、件数、面积、生卒年没核过就不要写死，
   用「据通行说法约…本库未核实」或 `gap` 块。

四、**`disputes` 必备，不许空，且要具体。**
   「学界仍在研究」这种废话不算。要写：谁的说法、争在哪一点、本库采纳哪个及为何。
   四态用 `adopt` / `pend` / `disp` / `dep`；**被推翻的旧说标 `dep` 而旧说史保留。**

五、**每写完一个文件立刻单独校验 JSON**，不要等全部写完再跑：
   ```
   python -c "import json,pathlib;json.loads(pathlib.Path('data/XXX/YYY.json').read_text(encoding='utf-8'));print('OK')"
   ```
   **一个写不出合法 JSON 的条目等于没写。**
   已有一路代理因为攒到最后才跑，一次写坏了六个文件。
   易错处：`{"t": "ul", "items": ["文本"]}` —— 字符串元素后面**不该有 `}`**。

六、**不许碰 `data/sources.json`。**需要新信源时写进 `plan/sources-<你的切片名>.json`
   （格式 `{"items":[...]}`，字段照 `data/sources.json` 的 items），由协调方合并。
   **并发写同一个信源文件会丢写。**正文里**不要引用未登记的 id**，会判死链。

六之补、**`sources` 只接受 `data/sources.json` 里登记的信源 id——实体不是信源。**
   本波已三次有人把**事件条目的 id** 当作 `sources` 的 `ref` 引用
   （`houma-dongshi-mu-excavation`、`zhongguo-jiade-chengli` 各出现过），一律报 ERROR。
   **事件、作品、遗址、类目、画论都是本库的实体, 不是出处**；
   要提到它们, 用正文链接 `[[event:xxx|名]]`, 不要写进信源栏。
   （画论是唯一的例外——它**既是信源也是研究对象**, 故 `data/sources.json` 里
   确有若干画论 id, 那种情况下引它是对的。）

七、**引用其它实体前先确认它存在**（`ls data/works/` 等）。
   不存在就用文字提及，**不要写 `[[kind:id]]`**——那会造死链。
   十二路在并发跑，别人正在建的东西你既不要等、也不要替它建。

七之补、**不要在正文里写出双方括号的占位形式。**
   `[[kind:id]]` 这个语法**没有转义机制**——你若在条目里写一句
   「本库尚无该遗址条目，故不作 `[[site:...]]` 链接」，
   **这句说明本身就会被链接检查当成一条链接，于是造出一条死链。**
   **谈论链接语法等于使用它。**要说明就用文字描述，如「故不建内部链接」。
   本波已有四路各自犯过这一处。

八、**若发现你要建的东西本库已有（题名不字面相同也算）——不要重建。**
   本波已出过三次「同物两条」。正确做法：**在报告里点名**，
   并在既有条目的 `alias` 字段里加上工单用的那个名字（这是唯一允许改动既有条目的操作）。
   `alias` 是「本条目还被叫作哪些名字」，**只在确实同指一物时写**——
   写错一条会让两件不同的东西在对账里合成一件，比少算更坏。

九、**判不出就不要硬凑。**判不出 facet、判不出分期、判不出材质，
   一律在 `disputes` 里说明判不出及为何，**不要挑一个最近的塞进去**。
   `class` 的 facet 只能取**十一档**之一：器类／窑口／书体／画科／流派／技法／纹样／
   材质／制度／考古学文化／**流通**。**取值有校验，写别的直接报 ERROR。**
   后四档是这两轮填缺口时被逼出来的:
   材质（黄花梨、紫檀）· 制度（官搭民烧、物勒工名、列鼎制度）·
   考古学文化（仰韶、良渚、红山——canon 的新石器 keys 原文即按考古学文化组织）·
   **流通**（画廊、拍卖、古玩市场、独立策展人——**同一类东西撞了五次才补**;
   依据是本库自己早已把展览史立为一等证据:「展览史就是接受史」）。

   `artist.cat` 同理已扩到**九档**：绘画／书法／篆刻／雕塑／建筑／工艺／**赞助／鉴藏／出版**。
   **这个字段回答的是「此人以何种身份进入美术史」，不是「他会做哪一门艺术」**
   ——忽必烈是敕命者、建安虞氏是书坊、曹寅是织造监督官，**都在美术史里占位置而都不是画家**。

   `work.kind` 另补了 **陶俑**（→雕塑组）与 **刻本**（→书画组，
   开宝藏一类跨百年的成套文本工程，**一部大藏经没有「画面」可分析**）。

十、**不动 `*.py`、不动 `data/outline.json`、不动别人切片里的条目。**

## 三、本库已确立的分寸，写作时一律遵守

- **「名在而物不可系」照戴逵条的写法**：名下无真迹者，一切技法面貌描述
  标明**转引自后世文献品评而非目验**，不予坐实。
- **摹本与原作分开**。canon 对魏晋南北朝的 dispute 原话：「顧愷之風格」「王羲之書風」
  由若干摹本与刻帖互相定义，存在循环论证。题名含「倣／仿／摹／臨」者当场标出。
- **「画派」不等于当时的组织形态**。题记给的是籍贯与师承，
  而「某某画派」多是近代美术史写作用来归拢作坊的概念——采纳师承，不采纳画派为自称。
- **拓本并入碑**，作为碑的补充；拓本等级用 `rubbing` 块六档
  （宋拓／明拓／清拓／近拓／翻刻／原石现状）。**不注明所据拓本，字口存损无从判断。**
- **重修层必备**（`relayer`）：不写重修就是把后代的画当原作讲。
- **断代依据独立成块**（`dating`）：十档依据 × 四级可靠度，
  **「风格比对」不许标「确证」——契约强制。**
- **评价要标明属何时口径**。近现代尤其：同一人在 1950／1980／2000 年代的评价
  可以完全相反，本库不追认任何一期的官方定评为事实。
- **迫害不得转换为艺术评价。**受过冲击不使作品更好，受过重用也不使作品更差。
- **「中西融合」禁用。**徐悲鸿动造型、林风眠动色墨关系、吴冠中动形式语言
  技术上不是一件事——要具体写动了哪个环节。
- **集体创作不许归于一人**。「总负责≠独自完成」（人民英雄纪念碑浮雕、穉英画室已立此例）。
- **流散要写清去向与交易链**，既不写成纯掠夺而不提本地中介与寺方处境，
  也不写成「保护性转移」为盗卖开脱。
- **图**：无图必须标 `image_status`（`copyright`／`no-free-image`／`lost`／
  `in-situ`／`pending`）。注意 `no-free-image` 断言的是「**已属公版**但无自由图」，
  与 `copyright`（仍在版权期）不是一回事，**别混用**。
  `in-situ` 的界定是「原址不可移动，**且现场禁摄或影像受管制**——
  露天可摄者不属此档，那是欠账」。**绝不伪造本地图片路径。**

## 五之二、把著录级壳升为完整级（与新建不同，另有五条）

一、**壳里已有的馆方字段一律保留，一个字都不要删。**
   它们是照录的一手著录：台北故宫一系带**印记资料（含印主）**、技法细目、尺寸、质地、
   数量与典藏页链接；克利夫兰一系带**递藏、展览史、题跋款识原文与英译、著录文献、CC0 图版**。
   **这些是事实层，已经补好了。你要加的是判断层。**

二、**不要重查已经照录好的东西。**看到印记清单，不要再去列一遍印；
   要写的是**这批印记意味着什么**——它记录的是这件物走过谁的手、
   何时进入内府、被哪一套鉴藏体系确认过。**清单是材料，接受史才是判断。**

三、**`id` 不变、馆方原题移入 `title_orig`（若尚未移）、`depth` 字段删除**（删掉即完整级）。
   参照 `data/works/npm-p-29.json`。

四、**`verification` 保持 `museum`，不要降为 `memory`。**
   本库此前两路做法不一：一路认为「新增阐释未经外部核对故降为 memory」，另一路保持 museum。
   **现定为保持。**理由：`verification` 描述的是**条目里的事实陈述经过何种核对**，
   而阐释层的可靠度由 `adopt/pend/disp/dep` 四态各自承担——那才是它该被评级的地方。
   把整条降为 memory，等于把已经核过的馆方字段一并说成没核过，**丢掉了真实的信息**。
   （若你新写的事实性内容超出馆方著录且未核，就把**那一条**标 `pend`，不要动条目级别。）

五、**壳若已带「本条与…同指一物」的互链，说明本库另有完整级条目。**
   **那种壳不在你的切片里**；若你发现漏网的，报告即可，不要升，也不要合并。

## 六、馆方核实：先读网页，不要因为没有 API 就放弃

**这是一条默认动作，不是可选项。**本库此前在多处写下「某馆无公开 API／无法核对」，
而 2026-08-06 实测证明：**那句话只对本库的抓取脚本成立，对读网页不成立。**

**已实测的可达性（每次用前仍应自己试一次，站点会变）：**

| 站点 | 实测结果 |
|------|---------|
| `digitalarchive.npm.gov.tw`（台北故宫典藏） | **通**。`/Painting/Content?pid={id}&Dept={P/U/...}` 一次请求即返回品名、作者、年代、質地、**分段尺寸**、文物統一編號 |
| **北京故宫** `www.dpm.org.cn/collection/paint/{数字id}.html` | **通，模式已坐实**。此前记的「实测 404」是因为 id 是猜的；**从 Wikidata 的 `P973`（described at URL）取真实 id 后，一路代理 6/6 次全部成功**。 |
| **故宫名画记** `minghuaji.dpm.org.cn/paint/detail?id=…` | **通**。同样从 `P973` 取 id。偶有条目返回首页，属该条无页而非站点不可达。 |
| `lnmuseum.com.cn`（辽宁省博物馆） | http/https 两种协议均 **socket closed**（与上博同一失败形态，区别于 403 拒绝、404 无此页）。该馆条目只能停在 `wikidata`。 |
| `digicol.dpm.org.cn`（故宫数字文物库） | 协调方一次实测报「域名安全校验不通过」；而一路代理实测**站点可达，但为 JavaScript 单页应用**，抓取只得到空壳搜索页。**两种失败原因完全不同**——前者无解，后者说明换个入口或许能通。**记录两次观察，不合并成一句。** |
| **克利夫兰开放 API** `openaccess-api.clevelandart.org/api/artworks/?q=&limit=` | **通，且是本波最有效的一条路**。返回题名、年代、材质、**尺寸**、藏品号、递藏、展览史、题跋释文、CC0 图像 URL。多路据此把条目升到 `museum`。**本库 `cma-*` 著录级壳有三百余条画作、八百余条陶瓷，均可经此核实。** |
| **大都会开放 API** `collectionapi.metmuseum.org` | **通**。多路核实成功，并可与 Wikidata QID 交叉确认。 |
| `asia.si.edu`（弗利尔／赛克勒） | 全程 403 |
| 哈佛／普林斯顿艺术博物馆检索页 | 纯前端渲染，取不到结果 |
| `www.shanghaimuseum.net` | 连接失败（socket closed）；**未能区分是站点问题还是并发下的资源耗尽** |
| `zh.wikipedia.org` | 有代理报告被拦 |

**两条操作纪律：**

一、**高并发与网页核实互相抢资源。**本波二十路并发时，有代理如实报告
「WebSearch 配额已被其他并发路线耗尽、WebFetch 被拦」，因而整批只能停在 `memory`。
**所以建条目（高并发）与核实（低并发）要分两段跑，不要指望一路里同时干成。**
**若你这一路的抓取普遍失败，如实写进报告并停在 `memory`——不要假装核过。**

二、**核到了就升档，核不到就说清卡在哪。**
`verification` 三档不是形容词：`museum` 断言你真的看过馆方页面。
**核到之后要把拿到的东西落地**——尺寸、藏品号、质地、纪年写进条目，
并把对应的 `gap` 块删掉（**填掉的缺口不该继续挂着**）。
**核不到时，写清是「站点不可达」还是「站点可达但无此件」——这两件事完全不同。**

**三、抓取摘要会静默篡改中文人名与编号，而结果看上去完全正常。**
**三路代理各自独立撞上，这不是偶发。**实测到的篡改：
「夏圭」→「夏禹」、「烟岫」→「烟囱」、「杜琼」→「杜堇」、
**「新00018626」→「皇00018626」、「盛懋」→「盛怀」**。
另一路又实测到六例，更严重：
「邹扩祖」→「乾隆扩祖」、「蔡嘉」→「蓝嘉」、**「王铎」→「王爺銅」**、
「蓝瑛」→「蓝莫」、「潘龄皋」→「潘龄墓」、「佚名」→「晰名」。
**「王铎」被读成「王爺銅」已经不是拼错，是换了个人。**

**定为纪律：中文文本（人名、题名、藏品号、款识）一律走原始 JSON／原始网页字节，
用 Python 解析；WebFetch 只用于读英文与结构化字段。**
两路代理改用原始 JSON 后，均报告「这类错误全部消失」。
**凡关键字段（作者、题名、纪年、尺寸），一律回原网页二次核对，不采信首次摘要。**
另有一次代理凭印象转述馆方字段，虚构了一行并不存在的「技法细目：Description」，
**是被 Write 工具的「文件已被修改」提示逼着重读才发现的**——
**写入前逐字核对已读内容，不凭记忆转述一手著录。**

**四、题名字面会骗人。**《王原祁艺菊图卷》的真实作者是**禹之鼎**，王原祁是**像主**。
**凡题名里出现人名，先判断那是作者还是画中人。**


三、**不要把可达性写进作品条目的 `gap` 里。**
