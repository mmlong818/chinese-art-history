# 国内馆开放数据 · 逐一实测

实测日期 2026-08-05。每项只发少量探测请求。

## 一、结论表

| 馆 | 可达 | 结构化接口 | 图像授权 | 判定 |
|---|---|---|---|---|
| 北京故宫 数字文物库 | 200 | **无。查询 JS 被商业混淆** | 未声明 | **不取** |
| 台北故宫 開放資料 | 200 | 详情页 HTML，id 连续可枚举 | **CC0（1MP）／CC BY 4.0（6MP）** | **可取，优先** |
| 国家博物馆 | TLS 握手失败 | — | — | 待另网核 |
| 上海博物馆 | 超时 | — | — | 待另网核 |
| 浙江省博物馆 | TLS 握手失败 | — | — | 待另网核 |
| 南京博物院 | 200 | 未细查 | — | 待查 |

国博、上博、浙博三处失败很可能是**本机网络环境**而非站点下线，
**不要据此写「该馆无开放数据」**——那是把探测失败当成事实。

## 二、北京故宫：不是难，是对方说了不

`digicol.dpm.org.cn` 首页 200。查接口时得到三条:

1. `/json`、`/api/list`、`/cultural/list`、`/searchList`、`/culturalRelic/list` 一律 **404**
2. `/list?page=1` 返回 **HTML（29 KB）而非 JSON**——服务端渲染分页
3. 查询逻辑在 `/js/dpms/list.js`，**281 KB，首行是 `var _0xodW='jsjiami.com.v7'`**
   ——jsjiami 是商业 JavaScript 混淆器

**第三条是决定性的。**混淆不是技术难度，是运营方主动装上的一层访问控制:
它花钱买了混淆器，就是在说不要程序化访问。
**逆向它去抓数据是绕过对方的明确表态，本库不做**——
与本库「一切图像与引用留原始链接」是同一条底线的两面:
尊重来源方的意思表示，不只在署名上，也在取用方式上。

故宫名画记（`minghuaji.dpm.org.cn`）另有极高清图，同样无开放接口，同上处理。

**可做的替代**: 故宫官网的展览页与藏品介绍是公开可读的人可访问内容，
**逐条人工核实**（把 `verification` 从 memory 升到 museum）是正当用法；
批量抓取不是。本库现有 dpm 信源正应这样用。

## 三、台北故宫：可行，且比 CAOD 更对口

`theme.npm.edu.tw/opendata` → 302 → `digitalarchive.npm.gov.tw/opendata`

### 规模（页面自述）

**108,653 件**。陶瓷 24,201 · **绘画 16,690** · 玉器 12,327 · 杂项 11,974 ·
钱币 6,953 · 铜器 6,236 · **书法 5,754** · 扇 2,545 · 珐琅 2,521 · 文具 2,385 ·
织品 1,612 · **拓片 1,214** · 漆器 762 · 雕塑 667 · 刺绣 438

### 授权（页面明文）

- **100 萬像素图档 ≈ 41 万张：公眾領域貢獻宣告（CC0）**，无需署名
- **600 萬像素图档 ≈ 41 万张 + 文字：CC BY 4.0**，须署名「國立故宮博物院」
- **取图不需注册**

**六百万像素是真图版级**——远高于本库「宽度 < 1000px 自动标图示级」那条线。
**这是本库第一个能拿到图版而非缩略图的渠道。**

### 端点

- 详情页 `/opendata/Pub/Detail/{id}?dep={U|B|C}&mode=full`（约 50 KB/页）
- 图像 `/opendata/Image/GetImage?imageId={id}&randomCode={n}`
- 落地页 `/opendata/Pub` 与 `/opendata/Pub/Index?dep=U` 返回同一 305 KB 页；
  `/opendata/Pub/List` 与 `/Home/List` 均 500——**没有可用的列表端点**
- **但详情页 id 连续可枚举**：实测 2383／2384／2385／2386 均 200、各约 50 KB

即摄入路径是**按 id 顺序走详情页并解析 HTML**。
代价要说清楚：108,653 页 × 约 50 KB ≈ **5 GB HTML**，礼貌限速下是数天的活。

### 字段粒度，比 CAOD 与克利夫兰都细

实测一条（`Detail/2383`，「臨池真賞」墨，清康熙五十五年）:

品名 · 分類 · **時代（带年號：清 康熙五十五年 1716）** · **文物統一編號** · 尺寸 ·
**題銘** · **人名款** · **年號款** · **收藏**

**四种题识分立**（題銘／人名款／年號款／收藏），
而 CAOD 只有两个（`comment_info` 题跋 / `stamp_info` 印鉴），
克利夫兰 61 个字段里只有一个笼统的 `inscription`。
- 「人名款」「年號款」直接对上本库 `dating` 块的 `款识` 依据
- 「題銘」「收藏」直接对上 `colophon` 块

**且它自带 holder——它就是藏家。**这正好解决 CAOD 的硬伤:
CAOD 有题跋著录而**没有现藏机构字段**，而本库 `work` 的 `holder` 必填。

## 四、一处必须记下的反面：它换掉了一种偏斜，又带来另一种

本库的来源偏斜问题原本表述为「2,482 件里 83.4% 出自克利夫兰、芝加哥、大都会」。
接入台北故宫能大幅改善这一条。**但不要把它当成偏斜问题的解决。**

**台北故宫是清宫旧藏。**
**修正「西方馆定义中国美术」，不等于修正「宫廷品味定义中国美术」。**
它的强项恰是宫廷来路的书画与器物；而它薄的三块，正是本库覆盖率最低的三块:

| 本库现状 | 台北故宫能补多少 |
|---|---|
| 秦汉 × 雕塑造像 **0/10** | 几乎不能——霍去病墓石刻、兵马俑是原址与考古品 |
| 辽金 × 墓葬美术 **5/15** | 不能——墓葬美术的证据是组合关系，散出即不可复原 |
| 各期 × 石窟寺 | 不能——原址不可移动 |

**这三块只能靠国内发掘报告，而发掘报告基本只有纸本。**
本库 `kaogu-wenwu` 信源的 note 已经写明「本库无法逐篇在线核实」——
**这不是可以靠换一个 API 解决的问题，它是纸本与在线之间的断层。**

所以正确的说法是: 台北故宫解决**传世品**这一半，
**考古出土的那一半仍然没有程序化渠道**，只能靠人读报告。

## 五、若开工，六条

1. **先只跑一个部门（dep=B 书画）的前若干条**，把 HTML 解析器验准，再放量。
   本项目已两次遇到「过滤没生效而返回全库总量」，**对照查验必做**：
   拿一个必然无效的 id 验证 404 行为。
2. **礼貌限速**，并在 User-Agent 里写明用途与联系方式（本库既有做法）。
3. **`verification` 可以标 `museum`**——台北故宫是藏家本身，
   这与 CAOD（聚合方，一律不得标 museum）的区别必须守住。
4. **图取 600 萬像素那一档并署名「國立故宮博物院」**；
   CC BY 4.0 的署名是义务不是礼节。低清那档 CC0 可不署，但本库照旧留原始链接。
5. **題銘／人名款／年號款／收藏 四字段要落成 `colophon` 与 `dating` 块，不要摊平进散文**
   ——这四个字段是要这个渠道的主要理由。
6. **本库已有 `npm-taipei` 信源且列为 tier 1，但此前是经 Wikidata 摄入的**
   ——馆方自己的开放数据一直没走过。这是个现成的错要改，不是新增渠道。
