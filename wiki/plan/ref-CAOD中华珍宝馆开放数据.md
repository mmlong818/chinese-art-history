# CAOD · 中华珍宝馆开放数据

`https://github.com/ltfc/CAOD` · 接口 `https://api.quanku.art` · CC0-1.0

## 一、仓库里没有数据

**先说清楚,免得误判工作量。**仓库 44 KB,四个文件:`LICENSE`、`README.md`、
`china_art_opendata_service.proto`、`china_art_opendata_service.swagger.json`。

**它是一份接口契约,不是数据集。**创建于 2021-03-19,**最后一次推送 2022-11-09**
——近四年未动。README 里的规模数字("精心校对 5,298 件""总量逾 18 万件""每月新增数百件")
都是 2022 年 10 月的口径,**现值未知**,要拿到凭证后读响应里的 `total` 字段才知道。

## 二、服务是活的,凭证是唯一的门

实测两次(各一个请求):

| 请求 | 结果 |
|---|---|
| 裸 POST,空 token | `HTTP 403 Invalid origin or referer` |
| 带 `Origin`/`Referer`,空 token | `HTTP 500 {"code":13,"message":"Cannot read properties of null (reading 'data')"}` |

第二个响应是 gRPC code 13(INTERNAL):服务端拿 token 去查、查到 null 又解引用了它。
**这说明请求已走到鉴权环节——服务完全在线,只是空凭证把它的空指针检查绊倒了。**

**门槛:** README 写明「发邮件到中华珍宝馆支持邮箱 support@ltfc.net,**说明学校与研究项目**,
审核通过后为你开 APPID 与 APPSEC」。
限流宽裕:**每分钟 500 次以内、每日 10 万次以内**。

**这是只有用户能做的事**(同 Smithsonian 的 api.data.gov key)。
且要留意:README 要的是「学校与研究项目」,而本库是公益网站不是学校,
**申请时得如实说明性质,不要为了过审把它说成别的东西。**

## 三、为什么这个来源对本库特别重要

本库最大的结构问题是来源偏斜:2,482 件作品里 **83.4% 出自克利夫兰、芝加哥、大都会**,
国内馆那 218 件里画作占 207,器物／石刻／窟寺／雕塑四组的国内来源合计 2 件。
**把摄入摊到三家西方馆并不解决这件事——分散只是让偏斜不那么显眼。**

而 CAOD 的字段表恰好补上了西方馆 API 一概没有的三样:

| CAOD 字段 | 本库对应 | 西方馆 API 有没有 |
|---|---|---|
| `comment_info` 题跋信息 | **`colophon` 块** | 无。克利夫兰 61 个字段里只有笼统的 `inscription` |
| `stamp_info` 印鉴信息 | **`colophon` 块(鉴藏印)** | 无 |
| `reference_book` 著录书籍 | **「著录与考订」与信源链** | 无 |

本库 `colophon` 块的立块理由原话是:「一卷宋画叠着元明清题跋与鉴藏印,
**递藏史刻在物上**,是中国书画独有的可见证据链。写成散文就查不了、统计不了。」
**CAOD 是本库评估过的第一个把这条主张变成可摄入字段的接口。**

## 四、它的词表比本库自己的细,其中一项暴露了本库的一个缺口

`style_type`(形制)14 值:立轴、**卷改轴**、**页改轴**、长卷、高头大卷、手卷、横披、
册页、散页、折扇、团扇、镜心、组屏、单屏

**「卷改轴」「页改轴」是本库该有而没有的一类证据。**
它说的是:**这件东西今天的形态不是它原来的形态**——长卷被改装成立轴、册页被拆成单页。
这与本库已有的 `relayer`(重修层,壁画经后代重绘)和 `rubbing`(拓本等级,
早拓与近拓字口不同)是**同一个认识论范畴:关于「你眼前看的究竟是什么」的证据**。
本库为壁画和碑刻都立了块,**而卷轴改装一直没有**——`kind` 只是笼统的「画作」。

另两个词表也比本库细:
- `material_type` 画材:水墨、焦墨、白描、指画、**浅绛、小青绿、大青绿、金碧**
  ——青绿的四级分档,本库画科／技法类目正缺这一层
- `media_type` 材质:纸本、泥金纸、靛蓝纸、紫色纸、洒金纸、笺纸、绢、绫、绸、布、
  **菩提叶**、**缂丝**

## 五、两处硬约束,摄入前必须先解决

**一、CAODItem 没有现藏机构字段。**
完整字段只有:`caodsn`、`age`、`name`、`author`、`desc`、`comment_info`、`stamp_info`、
`reference_book`、`media_type`、`material_type`、`style_type`、`size`、`tags`、
`subjects`、`technique`。

而本库 `work` 的必填项是 `["title", "kind", "period", "holder"]`——**`holder` 必填。**
**这是个反向的不对称:西方馆 API 永远有现藏机构而没有题跋著录,CAOD 恰好相反。**
所以 CAOD 记录不能直接落成 work 条目,要么另找现藏机构,要么为「藏所不明」立一档
——**而后者是契约决定,不是摄入脚本能顺手定的。**

**二、中华珍宝馆是聚合方,不是藏家。**
它的图像多为对故宫、台北故宫、辽博等机构藏品的扫描汇集。
**因此 CAOD 记录一律不得标 `verification: museum`**——本库该档的定义是
「馆藏官方页或考古报告逐条核实」,而聚合数据库不是馆藏官方记录。
读了 CAOD 就标 museum,等于把二手记录冒充一手。

同理,条目里要写「**经中华珍宝馆**」而不是「藏于中华珍宝馆」。
CC0 是中华珍宝馆对自己那份数据与扫描的声明,**不代表原藏机构放弃了主张**
——本库既定做法(一切图像与引用留原始链接)在此照旧适用。

## 六、若拿到凭证,该怎么摄入

1. **先读 `total`**,拿到现值,与 2022 年的 5,298 / 18 万对照——**别引用四年前的数字。**
2. **对照查验必做**:本项目已两次遇到「过滤没生效而返回全库总量」。
   分页参数是 `skip`/`limit`,拿一个必然为空的 `skip` 验证边界。
3. **先解决 `holder`**,再开摄入。不解决就跑,产出的是一批过不了校验的条目。
4. `age` → 分期映射走**题名/年代字符串的朝代前缀**那一路(`ingest_cn.py` 的
   `dyn_of_title` 已处理复合前缀「元明」的陷阱),不要用裸年份数值判。
5. **`comment_info` 与 `stamp_info` 要落成 `colophon` 块而不是塞进散文**
   ——这两个字段是本库要这个来源的全部理由,把它们摊平就白摄了。
6. `getDownloadUrl` 传 `caodsn` 换下载路径。取图前先核分辨率:
   本库图版政策是「**图示而非图版**」,宽度 < 1000px 自动标「图示级」。
